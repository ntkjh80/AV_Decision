# 자율주행 생성 영상의 권장 판별 기준

기준을 실제 JSON에 넣는 절차는 [판별 조건 작성 안내](CRITERIA_AUTHORING.md)에, 확률과 시간 정보의 의미는 [이론 설명서](THEORY.md)에 정리했습니다.

여기서 “좋은 영상”은 보기 좋다는 뜻만은 아닙니다. **무엇이 보이는지 설명할 수 있고, 그 설명을 뒷받침할 시간적 근거가 남아 있는 영상**을 뜻합니다. 어려운 날씨나 드문 사건도 학습에 필요하므로, 쉬운 장면만 남기는 기준을 만들지 않는 것이 중요합니다.

실행에 사용하는 기준은 [criteria.ko.json](../../src/av_decision/configs/criteria.ko.json)에 있습니다. 아래 설명과 JSON을 함께 읽으세요. 기준을 바꿀 때는 `rubric_id`도 바꾸고, 바뀐 파일을 결과와 함께 보관하세요. 보고서에는 전체 기준과 해시가 남습니다.

## 1. 처음에는 세 종류의 질문을 나눠 보세요

- **장면 조건:** 비·눈·안개·주간·야간처럼 영상에서 보이는 환경을 확인합니다.
- **사건:** 끼어들기·횡단·감속·간격 감소처럼 전후 변화가 필요한 행동을 확인합니다.
- **자료 품질:** 관측 가능성, 객체 소실이나 심한 변형 등 생성 결함을 확인합니다.

예를 들어 “비 오는 밤에 차량이 끼어든다”는 하나의 긴 문장 대신 `weather=rain`, `lighting=night`, `cut_in=yes`로 나눕니다. 날씨는 맞지만 사건은 없는 영상을 정확하게 설명할 수 있습니다.

사건 질문에서 `no`와 `unknown`은 다릅니다. `no`는 필요한 구간이 보였는데 해당 사건이 없다는 뜻입니다. `unknown`은 가림이나 짧은 구간 때문에 있었는지 없었는지 확인할 수 없다는 뜻입니다. 안 보였다는 이유로 음성 정답을 만들지 마세요.

## 2. 항목별 기준과 반례

| 기준 ID | 긍정 또는 해당 라벨을 줄 근거 | 잘못 판단하기 쉬운 예 | 보류해야 할 때 |
|---|---|---|---|
| `weather` | 비 줄기·물방울 등 현재 우천 단서, 광범위한 안개, 실제 강설 단서 | 젖은 도로만 보고 비가 내린다고 판단; 렌즈 오염을 안개로 판단 | 비와 안개가 섞여 단일 선택이 어렵거나 단서가 약함 |
| `lighting` | 주간 자연광, 야간의 하늘·조명 분포, 일출·일몰 무렵의 전환 조명 | 노출이 낮은 터널을 곧바로 야간으로 판단 | 자동 노출 변화나 시야 제한으로 구분하기 어려움 |
| `cut_in` | 옆 차로의 차량이 경계를 넘어 자차 진행 차로의 앞으로 들어오는 전후 장면 | 원래 앞에 있던 차량, 카메라 회전, 자차의 차선 변경 | 차선·차량을 추적하기 어렵거나 진입 전후 중 한쪽이 없음 |
| `pedestrian_crossing` | 사람이 도로 또는 횡단보도를 가로질러 이동하는 과정 | 인도에 서 있음, 카메라 이동으로 사람 위치만 달라 보임 | 차폐 뒤로 들어가 이동 방향을 확인할 수 없음 |
| `lead_braking` | 같은 선행 차량의 감속을 뒷받침하는 복수의 시각적·시간적 단서 | 제동등만 켜짐, 자차 가속으로 앞차가 커짐 | 자차 운동과 선행차 운동을 분리할 근거가 부족함 |
| `gap_closing` | 같은 선행 차량과 상대 간격이 줄어드는 일관된 전후 단서 | 줌 변경, 다른 차량으로 대상 전환, 화면 크기 변화만 사용 | 대상 추적 실패, 카메라/차량 운동의 혼동 |
| `continuity` | `consistent`: 샘플에서 명백한 생성 결함을 발견하지 못함; `artifact`: 설명되지 않는 객체 소실·심한 변형 | 자연스러운 가림·화면 밖 이동을 객체 소실로 판단 | 큰 프레임 간격 때문에 가림인지 결함인지 구분 불가 |
| `visibility` | `clear`: 주요 객체/도로가 보임; `limited`: 안개·가림·어둠 등으로 일부 정보 제한 | 안개라는 이유만으로 불량 영상으로 분류 | 입력 자체가 너무 모호하여 관측 상태도 판단 불가 |

`weather=clear`는 이 버전에서 비·눈·안개가 관측되지 않는 상태를 묶는 라벨이며, 흐린 날도 포함합니다. 기상학적 “맑음”과 같지 않습니다. “흐림”이 별도 학습 목표라면 `overcast` 선택지를 추가하고 정답을 다시 구축하세요. 복합 날씨도 필요하면 단일 선택을 다중 속성으로 다시 설계해야 합니다.

`lead_braking`과 `gap_closing`은 특히 조심해서 해석해야 합니다. 단안 영상의 상대 움직임만으로 실제 감속도와 거리를 알 수 있는 것은 아닙니다. 이 두 라벨은 검수 대상인 시각적 후보이며, 계측값의 정답이 아닙니다. 기준을 만족할 근거가 없다면 `unknown`이 올바른 답입니다.

## 3. 영상 의미 판정과 물리 검증을 구분하세요

| 확인하려는 주장 | 현재 S1에서 할 수 있는 일 | 추가로 필요한 근거 |
|---|---|---|
| 비가 오는 장면이다 | 우천의 시각적 단서를 재분류합니다. | 정밀 강우량을 말하려면 별도 센서/시뮬레이션 조건이 필요합니다. |
| 옆 차로 차량이 끼어든다 | 시간순 영상에서 사건 후보를 표시합니다. | 정확한 차선 ID, 대상 궤적, 가림 처리, 사람 검수가 필요합니다. |
| 앞차가 급제동했다 | 감속의 시각적 후보를 표시할 수 있습니다. | 시간별 속도와 가속도, “급”의 임계값 정의가 필요합니다. |
| 충돌 직전이었다 | 간격 감소 후보를 기록할 수 있습니다. | 좌표계가 맞는 거리·상대속도·경로·TTC 또는 시뮬레이션 접촉 검증이 필요합니다. |
| Transfer가 원본 기하를 보존했다 | 생성 영상 내부의 눈에 띄는 결함만 확인합니다. | 원본과 생성본의 시간 정렬, 객체 추적, 차선/깊이 비교가 필요합니다. 현재 미구현입니다. |
| 이 영상으로 학습하면 주행이 좋아진다 | 라벨 품질을 개선할 후보를 제공합니다. | 같은 조건의 학습 비교, 개루프 평가, 폐루프 시뮬레이션이 필요합니다. |

`consistent`를 “물리적으로 타당함”으로 번역하지 마세요. 샘플링하지 않은 프레임의 결함이나 비현실적인 마찰·가속도는 놓칠 수 있습니다. 실제 의미 개선 효과는 검수된 데이터와 후속 학습 실험으로 확인합니다.

## 4. 구간과 샘플링의 시작점

| 설정 | 스터디 기본값 | 선택한 이유와 조정 기준 |
|---|---|---|
| 사건 구간 | 사건 전후가 보이는 4~8초를 권장, 코드 최대 8초 | 한 장의 인상보다 사건 전개를 보려는 설정입니다. 사건이 길면 겹치는 구간으로 나누고 각각 라벨을 만드세요. |
| 샘플링 요청 | 4fps | 8초를 최대 32장으로 비교할 수 있습니다. 보편적인 최적값은 아닙니다. |
| 최대 프레임 수 | 32장 | 입력량을 제한합니다. 초과하면 자동 축소하지 않고 오류를 냅니다. |
| 최대 관측 공백 | 0.30초 | 기본 0.25초 요청과 원본 프레임 시각의 오차를 고려한 교육용 시작점입니다. |
| 원본 관측 주기 | 근거가 없으면 `null` | 파일 fps를 실제 독립 관측 빈도로 착각하지 않기 위해서입니다. |

예를 들어 10fps 영상에서 정확히 0.25초 시각의 프레임은 없을 수 있습니다. 실제로 0.0, 0.3, 0.5, 0.8초를 뽑았다면 최대 간격은 0.3초입니다. 이 실습은 요청한 4fps만 믿지 않고, 실제로 뽑은 프레임의 간격과 구간 양끝 공백을 확인합니다.

2Hz 관측은 원래 0.5초 간격입니다. 이를 10fps로 복제 저장해도 독립 관측 간격은 0.5초입니다. 최대 간격 0.30초 규칙을 통과하려고 `source_observation_hz`를 10으로 바꾸면 안 됩니다. 실제로 더 촘촘한 원본 관측을 확보하거나, 해당 실험에서는 보류된 이유를 그대로 기록하세요.

짧고 빠른 사건은 4fps로 놓칠 수 있습니다. 이때는 더 짧은 구간에 프레임을 늘리고, 사건 시작·진행·종료가 보이는지 사람이 먼저 확인하세요. 프레임을 많이 넣는 것만으로 모델이 움직임을 정확히 추론한다고 보장되지는 않습니다.

## 5. 확률과 임계값은 어떻게 쓰나요?

현재 자동 분기 기본값은 다음과 같습니다.

- 선택한 답의 확률이 0.80 이상이어야 합니다.
- 1위와 2위 선택지의 확률 차이가 0.20 이상이어야 합니다.
- `unknown`이면 점수가 높아도 보류합니다.
- 시간 관련 기준은 실제 샘플 간격과 원본 관측 주기를 함께 확인합니다.
- 목표 기준과 공통 기준 중 하나라도 위 조건이 부족하면 보류합니다.

**0.80과 0.20은 보정된 운영 임계값이 아닙니다.** 정해진 선택지 확률을 돌려주는 모델에서도, 0.9점이 실제 90% 정확도를 뜻하지 않을 수 있습니다. 한국어 질문의 표현과 선택지 구성에 따라서도 점수가 달라집니다. 초기 데이터에서 같은 임계값을 써 보고, validation 정답으로 항목별 오류를 확인한 뒤 수정하세요.

이번 코드는 단순한 공통 임계값으로 시작합니다. 조건별 임계값 최적화나 온도 보정은 구현하지 않았습니다. 실제 운영에서는 날씨와 끼어들기처럼 난도가 다른 항목을 별도로 보정하고, 그 절차를 따로 검증하는 것이 좋습니다.

Cosmos 자유 생성 응답의 숫자를 Valen 선택지 확률과 직접 비교하지 않습니다. 현재 Cosmos 어댑터는 확률을 사용하지 않으므로 기본적으로 사람 검수가 필요합니다. 두 모델이 동의하더라도 같은 종류의 실수를 할 수 있으므로, 동의를 정답으로 간주하지 마세요.

## 6. 권장 검증 실험

첫 실험은 학습 후보를 대량 생산하기보다, 기준이 잘 구분되는지 확인하는 데 집중하세요. 다음 구성은 연구 설계를 시작하기 위한 제안이며 통계적 성능을 보장하는 표본 수는 아닙니다.

1. 검수 가능한 수량의 실제/생성 영상을 모으고 원본 주행 그룹을 먼저 나눕니다. 같은 원본에서 만든 변형은 한 분할에 묶습니다.
2. 각 사건에 명확한 양성, 명확한 음성, 가림·저조도·짧은 구간을 포함합니다. 희귀 사건과 모델이 틀릴 법한 반례도 의도적으로 넣습니다.
3. 두 검수자가 가능하면 모델 답을 보기 전에 독립적으로 판정합니다. 불일치가 많으면 모델보다 기준의 정의부터 고칩니다.
4. validation에서 질문 표현과 임계값을 고릅니다. 최종 test는 고정한 뒤 한 번의 최종 비교에 사용합니다.
5. 원본, 생성본, 재분류 후 선택한 집합을 구분하여 품질과 라벨 분포를 비교합니다.

| 지표 | 확인할 내용 |
|---|---|
| 항목별 정확도 | 날씨·끼어들기 등을 한 숫자로 합치지 말고 각각 봅니다. |
| 오탐률 | 실제로 사건이 없는 영상에서 `yes`라고 한 비율입니다. |
| 미탐률 | 실제 양성 중 `no`라고 답한 비율입니다. 이번 함수는 `unknown`을 여기에 섞지 않고 별도 집계합니다. |
| 양성 중 판단 불가 | 실제 양성에서 `unknown` 또는 처리 실패인 수를 함께 봅니다. 미탐률이 낮아도 이 수가 크면 유용성이 낮습니다. |
| 보류율·처리 실패율 | 모델이 얼마나 많은 영상을 사람에게 넘기는지 확인합니다. 실패한 영상도 전체 분모에 남깁니다. |
| 검수 완료율 | 전체 검수 대상 중 사람이 정답을 작성한 비율입니다. 일부만 검수한 정확도는 범위를 함께 밝힙니다. |
| 조건별 보존율 | 안개·야간·가림·희귀 사건이 필터링 과정에서 과도하게 사라지지 않는지 확인합니다. |
| 지연시간·메모리 | 같은 입력과 장비에서 모델 로드 포함 시간과 준비 완료 후 시간을 나눠 측정합니다. |

`evaluate_human_labels`는 입력받은 정답 행에 대해서만 계산합니다. 정답 파일에 없는 영상까지 평가했다고 해석하지 마세요. 양성 예시가 없는 항목의 미탐률은 0이 아니라 `null`입니다. 실패 결과에 정답을 붙이면 `missing`과 해당 분모에 남습니다.

## 7. 재분류와 재생성은 언제 하나요?

| 상황 | 권장 처리 |
|---|---|
| 비·야간은 맞고 끼어들기는 분명히 없음 | 비·야간 및 끼어들기 음성 후보로 보존합니다. 원래 목표가 꼭 필요하면 수정 제안을 검토합니다. |
| 끼어들기 전후가 화면에 없음 | `unknown`으로 보류합니다. 먼저 구간 선택을 고치고 다시 관측합니다. 재생성을 먼저 요구하지 않습니다. |
| 안개가 짙지만 주요 사건은 확인 가능 | 어려운 장면으로 보존합니다. 안개 자체를 결함으로 보지 않습니다. |
| 차량이 가림 없이 순간 사라짐 | 생성 결함 후보로 격리합니다. 원본과 더 촘촘한 프레임으로 확인합니다. |
| 급제동 여부가 필요한데 속도 근거가 없음 | 영상 설명을 좁혀 기록하거나 필요한 궤적/센서 자료를 확보합니다. |

재생성 제안은 목표별 문장 템플릿입니다. 모델이 만든 자유로운 지시를 바로 생성 시스템에 전달하지 않습니다. 제안 문장만으로 객체 ID나 도로 형태가 유지된다고 보장할 수 없으므로, 원래 생성 프롬프트와 제어 조건을 사람이 함께 검토합니다.

기본 반복 한도는 총 2회입니다. 실패가 계속되면 횟수만 늘리기보다, 생성 가능한 목표인지, 입력에 필요한 전후 맥락이 있는지, 판별 조건이 과도한 주장을 하는지 먼저 확인하세요.
