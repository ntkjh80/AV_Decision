# 의미 재검증 기능의 실행 검증 기록

검증일: 2026-10-11. 이 문서는 코드가 실제로 확인한 범위와 앞으로 확인해야 할 범위를 나눠 기록합니다.

## Decision 독립 프로젝트에서 실행한 것

| 검사 | 결과 | 의미 |
|---|---|---|
| Python 단위 테스트 | 43개 통과 | 기존 판정·모델 선택 29개에 확신도 분류·이미지·분산 작업 테스트 14개를 추가했습니다. |
| S1 Jupyter 노트북 | 코드 셀 13개 실행, 오류 0개 | 실제 Jupyter 커널로 CPU 기본 경로를 실행했습니다. 공개용 원본에는 출력을 저장하지 않았습니다. |
| 문서·소스 검사 | 통과 | Python 구문, 로컬 문서 링크, 노트북 출력 제거 상태를 확인했습니다. |
| 배포 파일 생성 | wheel·소스 배포본 생성 성공 | 판별 기준 JSON과 라이선스가 설치 파일에 포함됩니다. |
| 새 가상환경에 wheel 설치 | 통과 | 원본 저장소 밖에서 기본 기준을 읽고 명령행 예제를 실행했습니다. |
| CPU 명령행 예제 | 6개 결과 생성 | 학습 후보 2, 재분류 후보 1, 보류 2, 생성 결함 검토 1로 분기했습니다. |

독립 패키지 검증은 Python 3.14.6에서 실행했습니다. 기존 AV 3.0 저장소에 처음 추가할 때는 기존 21개를 포함한 총 45개 테스트를 통과했으며, Decision 폴더로 옮길 때는 이 기능에 필요한 24개 테스트를 포함했습니다. 이후 모델 교체 5개, 확신도 분류·이미지 처리·분산 실행 14개를 추가해 현재 43개입니다. M4/M5의 생성 코드는 독립 패키지에 포함하지 않습니다.

GitHub Actions에는 Python 3.10·3.12·3.14 검사와 별도 노트북·배포 검사를 구성했습니다. 실제 GitHub 서버에서 실행한 결과는 아직 없습니다. 업로드 후 Actions 화면에서 확인해야 합니다.

실제 Valen 환경은 공식 모델 카드에 맞는 Python·PyTorch·Transformers 조합으로 따로 준비해야 합니다. CPU 경로의 성공이 모든 GPU 환경과의 호환성을 뜻하지 않습니다.

## 이론·조건 작성 문서와 시각화 추가 검증

- 문서의 로컬 링크, Python 예제 구문, SVG XML 구조를 검사했습니다.
- `road_wet` 조건 추가 예제를 실행해 후보 1개·재분류 후보 1개·보류 1개를 확인했습니다.
- 분기 시각화의 JavaScript 계산을 Python `judge()`와 108가지 설정·가상 사례 조합에서 대조했으며 모두 일치했습니다. 이 검증은 문서에 포함한 여섯 가지 가상 입력에 대한 일치 검사입니다.
- 브라우저에서 기본 분포, 확률 기준 강화 시 전체 보류, 허용 시간 공백을 늘렸을 때의 분기 변화를 확인했습니다.
- 문서용 SVG 그림 3개의 실제 표시를 확인했습니다. GitHub에서 렌더링되는 Mermaid 도식도 함께 제공하지만, GitHub 서버에서의 표시를 직접 검증한 것은 아닙니다.

이 검사는 설명과 코드가 일치하는지 확인하는 절차입니다. 실제 영상에서의 분류 정확도를 측정한 결과는 아닙니다.

## 신규 테스트에서 확인한 사항

### 확신도 폴더 분류·이미지·GPU 작업 배정

- 확신도 0.90·0.80 경계와 `unknown`, 점수 없음, 처리 실패를 구분했습니다.
- 실제 임시 파일을 복사해 원본 보존, 파일 이름 충돌 방지, JSON 구간 정보, 복사본 내용을 확인했습니다. 영상 복사 테스트의 바이트는 추론용 실제 영상이 아닙니다.
- 모델 선택 확률과 목표 선택지 확률이 CSV에서 구분되는지 확인했습니다.
- 상황 폴더의 항목이 목표에 없어도 점수 검사에 들어가는지 확인했습니다.
- 추론 뒤 원본이 바뀌면 해시 불일치로 복사를 취소하고, 없는 파일과 처리 실패도 집계하는지 확인했습니다.
- 단일 이미지는 시간 사건을 `unknown`으로 남기면서 날씨 같은 정적 조건을 분류할 수 있음을 확인했습니다.
- Pillow로 실제 작은 PNG를 읽어 단일 이미지 요청·해시·시간 정보 없음 처리를 확인했습니다. Pillow 미설치 환경에서는 이 테스트 한 개를 건너뜁니다.
- 실제 `spawn` 프로세스와 가상 모델로 입력 순서 유지·판정 일치·비정상 종료·시간 초과·대기 입력 보존을 검사했습니다. 실제 CUDA 연산 검증은 아닙니다.
- 색상 이미지 8개를 만든 가상 응답 예제를 실행해 높은 구간 2개, 중간 2개, 낮음·판단 불가·점수 없음·처리 실패 각 1개와 전체 8개 복사를 확인했습니다.
- HTML 보고서의 확신도 분포와 파일별 점수·폴더 집계 표시를 브라우저에서 확인했습니다.

실제 GPU 여러 장에서의 Valen 실행과 처리량·VRAM 측정은 아직 수행하지 않았습니다. 분산된 모델 가중치 하나를 여러 GPU에 나누는 모델 병렬 어댑터는 구현하지 않았으며 추가 설계를 문서에 구분했습니다.

### 모델 설정과 교체 기능

- `valen`, `cosmos-http`, `vlm-http`를 공통 생성 함수로 선택할 수 있습니다.
- JSON 파일의 상대 모델 경로는 설정 파일 폴더 기준으로 해석합니다. 설정을 읽기만 할 때 GPU 모델을 로드하지 않습니다.
- 지원하지 않는 키, 잘못된 버전, 비어 있는 revision, 잘못된 샘플링 값은 실행 전에 거부합니다.
- 새 `--provider-config` 방식과 기존 개별 옵션 방식으로 실제 CLI 함수를 실행하고, 모의 HTTP 응답이 보고서까지 이어지는 것을 확인했습니다.
- HTTP 모델 이름이 요청에 반영되고, 생성된 확신도를 확률로 사용하지 않으며, 사람 검수 대상으로 남는지 확인했습니다.
- 설정 파일과 개별 옵션을 함께 주면 모호한 덮어쓰기 대신 오류를 반환합니다.
- 변경한 노트북의 CPU 코드 셀 13개를 다시 실행했습니다. 실제 모델 실행 셀은 기본값대로 건너뛰었습니다.
- 새 모듈을 포함한 wheel과 설정 예제·문서를 포함한 소스 배포본을 만들었습니다.

HTTP 서버와 GPU 모델은 모의 객체로 대체한 계약 테스트입니다. 실제 모델 간 정확도나 서버의 종단 호환성을 측정한 것은 아닙니다.

### 공통 판정과 입력 처리

- 생성 목표와 관측 라벨이 서로 덮어써지지 않습니다.
- 관측 제한이 있는 장면을 무조건 결함으로 버리지 않습니다.
- 누락된 질문, 잘못된 선택지 확률, NaN, 확률 합 오류를 거부합니다.
- `unknown`을 사건이 없다는 정답으로 바꾸지 않습니다.
- 원본 2Hz 관측이나 미확인 관측 주기는 10fps 저장 여부와 관계없이 보류됩니다.
- 불확실한 생성 결함은 검토 대상으로 남습니다.
- 시험 분할·미지정 분할·반복 횟수 소진 시 재생성 제안을 보류합니다.
- 같은 원본 그룹이 한 배치에서 다른 분할에 들어가면 오류를 냅니다.
- 모델 응답 실패도 보고서와 사람 검수 CSV에 남습니다.
- 기존 출력 덮어쓰기와 영상 폴더 밖을 가리키는 manifest 경로를 거부합니다.
- 원격 버전의 모듈 번호에 의존하지 않고 `condition`/`scenario` 필드를 읽습니다.
- 급제동·충돌 직전이라는 강한 주장을 시각적 단서로 자동 치환하지 않습니다.
- 평가에서 모델의 판단 불가와 처리 실패를 양성 정답의 분모에서 숨기지 않습니다.
- Cosmos 요청에 원래 파일명·생성 프롬프트를 넣지 않고 실제 시각 순서의 이미지를 보냅니다.
- Cosmos가 반환한 임의 확신도는 선택지 확률로 사용하지 않습니다.
- Valen의 질문 형식과 `shared_state` 호출 계약을 확인했습니다.
- 디코더 대역을 이용해 실제 PTS 간격 처리, 중복·역전·누락 시각, 프레임 한도 초과, 긴 영상 거부를 확인했습니다.

## 아직 실행하지 않은 것

이번 환경에서는 GPU 가중치를 불러오거나 실제 주행 영상으로 모델을 추론하지 않았습니다. 따라서 다음 항목은 **미검증**입니다.

- 실제 Valen snapshot의 한국어 질문 이해와 자율주행 사건 판별 정확도
- 실제 Cosmos 서버의 멀티이미지·순수 JSON 응답 및 설치 환경 호환성
- 실제 MP4 코덱별 PyAV 디코딩과 프레임 추출의 종단 실행
- 실제 GPU 메모리 사용량, 최초 로드 시간, 준비 완료 후 지연시간, 처리량
- 원본/생성본의 시간 정렬 및 기하 보존 여부
- TTC·감속도·접촉 등 물리량의 검증
- 재분류 자료로 학습한 정책의 개루프·폐루프 성능 개선

모델·HTTP·디코더 연결 테스트에는 작은 대역을 사용했습니다. 외부 시스템을 실제로 실행했다는 의미는 아닙니다. CPU 예제의 확률과 정답도 학습용으로 만든 값입니다.

## 재실행 방법

Decision 폴더에서 먼저 `python -m pip install -e .`로 설치한 뒤 다음 명령을 실행합니다.

```bash
python3 -m unittest discover -s tests -v
python3 -m av_decision demo --out .study-runs/semantic-check-001
python scripts/check_repository.py
```

노트북은 `IMPORT_REAL=False`, `RUN_REAL=False` 상태에서 커널을 재시작하고 전체 셀을 실행하면 됩니다. 같은 출력 이름의 명령행 실행을 반복하려면 새 출력 폴더를 지정하세요.

실제 모델 검증 때는 [기술 설명서](SEMANTIC_VIDEO_GUIDE.md)의 입력 준비 절차와 [권장 판별 기준](SEMANTIC_CRITERIA.md)의 검수·평가 항목을 함께 사용하세요. 모델 버전, GPU, 원본 그룹, 프레임 시각, 보류율, 실패율을 빠뜨리지 않고 기록하는 것이 다음 검증의 출발점입니다.
